# Veo front end

A three-page Next.js app over `demo_pipeline.py`: a form, an API route that
spawns the Python pipeline, and a results page.

## What it does

- Takes a persona, budget, rent/buy flag and destination.
- `POST /api/recommendations` spawns `python demo_pipeline.py ... --no-explanations`,
  parses the pipeline's stdout, and returns the top three.
- The results page renders each area's composite score and per-factor breakdown
  from `sessionStorage`.

Explanations are always skipped here (`--no-explanations` is hard-coded in the
route), so the Anthropic key is not needed to use the web UI.

**On the numbers shown**: the prices, Ofsted ratings and — with no `TFL_APP_KEY`
— the commute times are synthetic placeholders generated by the Python workers.
Only the crime and amenity figures come from a live API. See the provenance
table in the [root README](../README.md).

## Running it

```bash
npm install
npm run dev     # http://localhost:3000
```

The Python side must be installed too (`pip install -r ../requirements.txt`),
because the API route shells out to `../demo_pipeline.py`.

## Stack

Next.js 14 (App Router), TypeScript, Tailwind. No other runtime dependencies —
see `package.json`.

## Layout

```
frontend/
└── app/
    ├── page.tsx                        # form
    ├── results/page.tsx                # results
    ├── api/recommendations/route.ts    # spawns the Python pipeline
    ├── layout.tsx
    └── globals.css
```

## Known rough edges

- The route parses the pipeline's human-readable stdout with regexes. Change a
  print statement in `demo_pipeline.py` and the UI breaks silently.
- A pipeline run takes as long as the Python fetchers take; there is no
  streaming, no progress and no timeout beyond the request's own.
- There are no tests.
